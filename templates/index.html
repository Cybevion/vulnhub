An intentionally vulnerable web app for teaching web security. Every module has a vulnerable mode and a safe/patched mode, side by side.

🧭How VulnLab Works
① Pick a module
Use the top-bar category dropdowns or the left sidebar to open any of the {{ 16 }} vulnerability demos.
② Exploit it (VULNERABLE)
Each page opens in vulnerable mode. Click a payload in the right sidebar (it loads into the form) and submit.
③ Inspect the request
The Request Inspector beside the form shows the exact HTTP request and a copy-paste curl.
④ See the fix (SAFE)
Flip the mode switch at the top to safe and re-run the payload — the exploit no longer works.
⑤ Understand why
Use 🔑 Show the fix (diff) for a line-by-line before/after, and 💡 hints if you get stuck.
⑥ Teaching?
🖥 Present (top bar) enlarges text and lifts contrast for a projector. Hide reference collapses the right sidebar.

Welcome to VulnLab 👋

A hands-on lab for learning web vulnerabilities — and their fixes. Here's the 60-second version.

1Every module has two modes. A VULNERABLE version and a SAFE (patched) version, flipped with the mode switch at the top of each module page. Pages open vulnerable by default.
2Pick a module from the top-bar category dropdowns or the left sidebar.
3Exploit it. Click a payload in the right-hand reference sidebar — it loads straight into the form. Submit and watch it work.
4Inspect & learn. The Request Inspector shows the raw HTTP request; 🔑 Show the fix (diff) reveals exactly what changed to patch it; 💡 hints nudge you if stuck.
5Flip to SAFE and re-run the same payload — the attack no longer works. That contrast is the whole point.
6Teaching a class? Use 🖥 Present for a projector-friendly view. Some modules (SSTI, Command Injection, Deserialization, XXE) run real code — that's intentional, and contained to this lab.
